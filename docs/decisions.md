# 技术决策与验收边界

本项目参考《Super-agent 设计探索：迈向更自主的 Agent 系统》中的架构思想，自行实现可重复验证的本地核心。不包含该文章全文、原型代码或真实业务记录。

## 001：统一事件先于平台连接器

**已实现。** Event 显式包含 source/source_id/thread/actor/kind/text/occurred_at/reply_to；内部 Event 与 Thread 使用确定性 UUID，正文保持原样。源 ID 必须稳定；不使用文字 hash 冒充消息身份。

程序准入由宿主策略决定，语义判断由 Router 完成。被过滤事件保留在持久日志，但不触发模型。JSONL 是第一种真实接入与交付机制，平台名字只作为事件源标签，不等于完成平台集成。

验收：重放无重复任务；同源 ID 改内容会报冲突；不同源同 ID 不冲突；过滤后不调用模型；未完成的输入行等待生产者补齐。

## 002：SQLite 是状态真相，模型 Session 是可引用的计算上下文

**已实现本地连续性。** 事件、Thread、任务版本、输入关联、订阅、决策、运行尝试、Session 引用及 Outbox 分开存。每批 Router 决策原子提交；Worker 使用 token 和 run_revision 防止旧结果覆盖新状态。

Codex backend 按回合启动进程并恢复明确的 Session ID；不是每次新建短会话。Router 只有一个逻辑 Session，各任务各自隔离。模型实际历史仍由本机 CLI 管理；会话引用与状态库可重开不代表可以把模型历史直接迁移到另一设备。

验收：Demo backend 的数据库重开测试，以及真实 CLI 的 Router/Worker 双角色恢复测试。崩溃发生在 Session ID 提交之前时，私有 run 日志可能有更多历史，系统不声称自动恢复该不确定回合。

## 003：确定的归属走订阅直通

**已实现。** 新话题经 Router 冷启动；事件与任务明确关联后建立 Thread→Task 订阅。后续事件直接增加对应任务输入及版本，不再调用 Router。关系是多对多，支持跨来源同任务和同话题多个任务。

Worker 返回 handoff 时，把指定输入送回 Router 并取消该任务对相应话题的订阅；该事件可以被显式重新关联。结果受众仍为最初发起话题，输入订阅不自动授予输出权限。

验收：后续事件不增加 router_calls；另一来源可关联同任务；多播覆盖所有订阅任务；handoff 后新事件重新进入 Router。

限制：订阅以适配器提供的真实话题边界为前提。对没有话题结构的大群，需要另做话题划分，不能把群 ID 当万能任务 ID。

## 004：摘要有预算，完整内容有下一跳

**已实现基础 Inline/Spill 与链式召回。** 初始提示只带预算内的摘要和 index_file。完整 Event/Thread/Task 分开物化为 JSON，正文不截断，每个对象引用下一跳文件。模型可以读取文件逐级展开；CLI 同时提供 recall 命令。

验收：超长多行/emoji 原文存储完整，初始上下文不超预算；Event→Thread→Task→另一 Thread 的引用链可遍历。

限制：当前按相关连通图物化文件，没有按需远程检索服务器、分页或向量检索。大图会增加磁盘与构建开销；先保留正确引用，再用性能数据决定引入分页端点。

## 005：接收、协调、执行解耦

**已实现任务级异步。** 一个轻量调度循环持续接收输入、直通事件并提交 Router/Worker 工作。线程池运行独立模型子进程；单任务同一时刻只允许一个运行尝试。运行中收到补充后增加 revision，当前结果标记 superseded，随后处理下一版本。

验收：Worker 被测试栅栏阻塞时，新事件仍能入库；补充不覆盖正在执行的版本。

限制：尚未实现模型回合中的实时消息注入或任务级 stop 工具。当前是回合边界续接；STOP 是整个实例的所有者控制，不能说已完整实现文章的全双工 ReAct Loop。

## 006：完成报告和验收结果分开

**已实现。** Worker 只报告 status/summary/artifacts/handoff。运行时独立检查文件存在、路径范围、大小和 SHA-256。匹配所有者预置的文件哈希才为 succeeded；缺少或不匹配预期为 needs_review；依赖缺失为 needs_input。

验收预期来自启动时读取的宿主 policy，不能由外部事件或 Worker 自己生成。真实模型测试的文件最终也由宿主读取核验。

限制：目前只有固定产物的哈希验收，没有可信测试运行器、人工审批记录或部署验收；也不验证任意软件的功能正确性。

## 007：Watchdog 必须能看见主服务死亡

**已实现独立的基础设施监督。** supervisor 是独立进程，持有自己启动的 child 句柄，检查退出与原子心跳文件，必要时终止旧子进程及其后代并重新启动。运行时内部处理过期任务租约；不确定任务转为 interrupted，不因主服务重启而自动重复执行。

验收：真实子进程故障注入，确认不同 child PID 再次出现。Windows/Linux CI 都运行这项测试。

限制：supervisor 自身仍应交给 OS 服务管理器；当前没有语义进展判断、自动修复代码或跨机器 Watchdog。POSIX 的 ps 进程树快照和 Windows taskkill 不是容器级进程隔离；更强保障需要 Job Object/cgroup。

## 008：交付必须是持久的外部效果

**已实现本地 JSONL 投递闭环。** 写入、flush、fsync 完成后才 ack；输出含持久实例身份及 outbox 编号。若写完但 ack 前崩溃，重启可以从目标文件识别已交付编号，避免再次追加。检测到输出残缺尾部则停止并要求检查，不静默掩盖数据损坏。

验收：故障注入到 fsync 后、ack 前，再次运行输出字节不增加，Outbox 最终确认。

限制：这只证明此文件适配器的行为。未来 Slack、邮件或 GitHub 连接器必须分别处理回执、幂等和权限；不能沿用文件测试声称跨平台 exactly-once。

## 010：凭据和权限属于宿主

真实 backend 沿用本机 CLI 登录，不复制认证文件。只读取模型/provider 连接与现有 Windows 沙箱选项；隔离用户 MCP/hooks 和无关环境变量，关闭工具网络及 Web 搜索，保留执行规则。只读 Router 与任务目录写入 Worker 使用不同沙箱模式。

这不是多租户安全边界。模型会接触外部不可信输入，CLI 沙箱也不保证完全隔离宿主读取。接受真实不可信来源前，必须用专用 OS 身份或容器承载执行环境，并在连接器外托管凭据；不要把个人凭据放进模型上下文。
